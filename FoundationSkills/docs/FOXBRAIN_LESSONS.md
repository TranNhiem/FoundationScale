## Conflicts between documents (unresolved; do not encode either side as fact)

- refit_every guidance conflicts: RL_ACCEL_FINAL_REPORT mandates refit_every=1 + K=1 as THE collapse cure, while EXPERIMENTS_LEDGER/EXPERIMENTS_AND_FINDINGS run healthy FACTS/SDPO-RT with refit_every=200 and attribute the cure to anchor-in-target mixture (and note refit is 'a visibility aid, not a trigger'). Likely reconcilable (K bounds trajectories in-flight; refit cadence governs teacher refresh) but unresolved in the docs — C24/C25 encode the conservative union.
- Judge max_tokens measured values differ by doc: 2560 for ~19 criteria (M1M4-JUDGE-README), 4096-8192 for CJK bounded JSON (RL_ACCEL), and 3072 to fit a 16384-window judge's input (ODPO §5). No single default; rule should be max_tokens ≤ window − max_input with a completeness check on the verdict JSON.
- The claim 'Muon looks worse than AdamW' is invalidated by expert aliasing (EXPERT_ALIASING_VERDICT), yet MUON_RUNBOOK's own throughput comparison (52-56 vs 28-52 s/iter) conflates optimizer cost with forced no_shard + fuller recompute — neither doc supports a clean Muon-vs-AdamW conclusion; treat all such numbers as confounded (encoded in C19).
- FS trains with FULL-SEQUENCE loss (no assistant masking); FoxBrain facts about assistant-span masking, KEEP_COT patches, tool_response not-supervised, and '0 supervised tokens' are masking-trainer-specific. The prefix alignment (C3) and stop-token (C4) facts DO transfer, but any masking-parity checks must be re-derived for FS semantics rather than copied — flagged so no one ports the masking invariants verbatim.
- SFT hyperparam 'official protocol both arms' (lr 5e-5) vs as-shipped 31B running 10x cold is unresolved in the source ('UNVERIFIED whether intentional', §9 open items) — C6/C15 assume 5e-5 but the readiness check should require explicit LR so intent is never implicit.
- Video sampling conventions differ per model and both are 'measured': Nemotron uses MAX_VIDEO_FRAMES=128 at 32K (260 tok/frame) while Gemma4-26B recommends fps=1/nframe_max=24 at 16K (280 tok/frame) — not a contradiction, but family cards must carry per-model values or configs will silently cross-apply.
- Facts marked hypothesis/recommended (SDPO-R FP 6.5%, DR tokenizer-drift hypotheses, E4-MIX single-variable test, ODPO leader-rollout refactor cause, M1-M4 judge 'built + CPU-tested, never used live') are included only where they gate safety behavior; live-validated status is noted — do not treat M1-M4 judge numbers as production-measured.
